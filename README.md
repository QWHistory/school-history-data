# 🏛️ 校园历史数字化项目 (QWHistory)

本项目是一个面向校友和在校生的在线校史投稿与展示系统。核心架构采用**飞书多维表格 (收集与审核)** + **GitHub (数据永久存储)** + **Cloudflare Pages (网页展示)**，实现完全免登录投稿、自动化数据同步和极低维护成本。

## 📁 仓库结构说明
- `/index.html`：项目门户首页。
- `/weekly-digest/index.html`：校史档案展示画廊。
- `/data.json`：所有审核通过的档案数据（由脚本自动生成，**请勿手动修改**）。
- `/images/`：所有档案的附件（图片、文档等）。
- `/sync_history.py`：从飞书拉取数据并同步到 GitHub 的 Python 脚本。
- `/.github/workflows/sync.yml`：GitHub Actions 自动化配置文件（每天定时运行同步脚本）。

## 👑 核心红线（严禁违反）
1. **账号绝不共用**：所有的平台账号（飞书、GitHub、Cloudflare）均由总负责人实名注册。换届时，通过“组织所有权转移”或“添加新管理员”完成交接，严禁直接给下一届发送账号密码。
2. **密钥绝不泄漏**：任何情况下，都不要把飞书的 `App Secret` 或 GitHub 的 `PAT Token` 明文写在代码里或发给别人。

## 🛠️ 日常运维指南

### 场景一：如何审核校友的投稿？
1. 登录飞书，打开“校史投稿信息表”。
2. 检查新提交的记录，核实内容合规性。
3. 审核通过：将“审批状态”单选字段改为 **`通过`**。系统会自动记录审批人和时间。
4. 审核不通过：修改状态为 `驳回`，并删除该条记录（或将状态改为已处理）。
*(注：系统每天北京时间早上 8 点会自动将“通过”的数据同步到网页，并自动清理飞书表格中的旧数据，保持表格轻量。)*

### 场景二：如何立即更新网页？（不想等每天的定时任务）
1. 进入 GitHub 仓库，点击顶部的 **Actions** 标签页。
2. 在左侧点击 `Feishu to GitHub Sync`。
3. 在右侧点击 **Run workflow** 下拉框，点击绿色的 **Run workflow** 按钮。
4. 等待约 30 秒，看到绿色对勾即代表数据已更新（Cloudflare 随后会自动部署网页）。

### 场景三：如何修改网页配色或文案？
- **修改首页**：编辑根目录的 `index.html`。
- **修改档案页**：编辑 `/weekly-digest/index.html`。
- **修改联系邮箱/举报信息**：在 `/weekly-digest/index.html` 搜索 `generateReportLink` 函数，替换里面的邮箱地址。

## 🚑 故障排查手册（3个高频报错）

### 1. GitHub Actions 报错（脚本运行失败）
- **表现**：Actions 页面出现红叉。
- **排查**：
  - 点开报错详情，如果是 `401 Unauthorized`，大概率是飞书的 `App Secret` 过期或填错了。
  - 如果是 `403 Forbidden`，大概率是飞书应用没有给多维表格“可编辑”权限。
- **修复**：去 GitHub 仓库的 `Settings -> Secrets and variables -> Actions` 里更新对应的密钥。

### 2. Cloudflare Pages 部署失败（网页打不开/白屏）
- **表现**：域名打开报错，或者 Cloudflare 提示 Build Failed。
- **排查**：
  - 检查仓库里是否有 `index.html`。
  - 检查 `data.json` 格式是否合法（可以通过 JSON 在线校验工具检查）。
- **修复**：如果代码没问题，可以在 Cloudflare Pages 后台点击 "Retry deployment"（重新部署）。

### 3. 飞书 API 无法获取数据
- **表现**：脚本提示“获取到 0 条待同步记录”，但飞书里明明有数据。
- **排查**：
  - 检查飞书表格里的状态字段是不是**单选**类型。
  - 检查代码里读取的字段名（如“审批状态”、“通过”）是否与飞书表格里的实际名称**完全一致**（包括大小写和空格）。

## 🔄 换届交接清单（Checklist）

当下一届负责人接手时，请核对以下清单：

- [ ] **飞书**：已将新负责人添加为多维表格的“所有者”或“可管理”协作者。将飞书应用（校史同步）的开发者权限转移给新负责人。
- [ ] **GitHub**：已将新负责人邀请进入 `QWHistory` 组织，并赋予 `Owner` 权限。
- [ ] **Cloudflare**：由于 `*.pages.dev` 域名不能跨账号转移，新负责人需用自己的账号重新绑定 GitHub 仓库并部署一次（选择纯静态，Build command 留空，Output 目录填 `/`）。
- [ ] **密钥**：通过密码管理器（如 1Password/Bitwarden）将 `App Secret` 和 `GitHub PAT` 安全地交接给新负责人。
- [ ] **本手册**：确认新负责人已经完整阅读了本 `README.md`。
