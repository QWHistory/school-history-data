# 清湾校史档案馆（非官方）

本项目是一个面向校友和在校生的**清华大学附属中学湾区学校（清湾）非官方**校史投稿与展示系统。核心架构采用 **飞书多维表格 (收集与审核)** + **GitHub (数据永久存储)** + **Cloudflare Pages (网页展示)**，实现完全免登录投稿、自动化数据同步和极低维护成本。

## 仓库结构

- `/index.html`：项目门户首页。
- `/archive/index.html`：校史档案库列表页（包含完整的搜索、筛选功能）。
- `/record1.html`：**档案详情页的“物理模板”**（请不要直接访问此文件，它是由路由间接调用的）。
- `/submit/index.html`：投稿须知与飞书表单内嵌页。
- `/weekly/index.html`：本周校史摘要预留页面。
- `/data.json`：所有审核通过的档案数据（由脚本自动生成，**请勿手动修改**）。
- `/images/`：所有档案的附件（图片、文档等）。
- `/assets/`：全局 CSS 样式（`style.css`）与 公共 JS 逻辑（`common.js`）。
- `/sync_history.py`：从飞书拉取数据并同步到 GitHub 的 Python 脚本。
- `/_worker.js`：**核心路由拦截器**（下文有详细说明）。
- `/.github/workflows/`：GitHub Actions 自动化配置（每日同步与每周备份）。

## 核心红线

1. **路由机制警告（极其重要）**：
   - 本项目的详情页 URL 格式为 `/archives/档案编号`。
   - **绝对不要**在根目录创建名为 `archives` 或 `record` 的物理文件夹。
   - **绝对不要**修改 `_worker.js` 的逻辑，也**绝对不要**试图用 `_redirects` 文件去替代 `_worker.js`。因为 Cloudflare Pages 底层的 URL 规范化机制（308 重定向）会吃掉 `/record/` 后面的参数，只有 `_worker.js` 的边缘计算拦截才能完美保住原始 URL 并返回 `record1.html` 的内容。别问我怎么知道的。能跑就别动。
2. **账号绝不共用**：所有的平台账号（飞书、GitHub、Cloudflare）均由总负责人实名~~（有吗，好像没有，反正是个人账户）~~注册。换届时，通过“组织所有权转移”或“添加新管理员”完成交接，严禁直接给下一届发送账号密码。
3. **密钥绝不泄漏**：任何情况下，都不要把飞书的 `App Secret` 或 GitHub 的 `PAT Token` 明文写在代码里或发给别人。

## 日常运维

### 场景一：如何审核校友的投稿？
1. 登录飞书，打开“校史投稿信息表”。
2. 检查新提交的记录，核实内容合规性。审核员有高权限，可以修改提交内容，请慎重。
3. 审核通过：将“审批状态”单选字段改为 **`通过`**。系统会自动记录审批人和时间（大饼，目前只能审核不能记录）。
4. 审核不通过：修改状态为 `驳回`。

*(注：系统每天北京时间早上 8 点会自动将“通过”的数据同步到网页，并自动清理飞书表格中的旧数据，保持表格轻量。)*

### 场景二：如何立即更新网页？（不想等每天的定时任务）
1. 进入 GitHub 仓库，点击顶部的 **Actions** 标签页。
2. 在左侧点击 `Feishu to GitHub Sync`。
3. 在右侧点击 **Run workflow** 下拉框，点击绿色的 **Run workflow** 按钮。
4. 等待约 30 秒，看到绿色对勾即代表数据已更新（Cloudflare 随后会自动部署网页）。

## 故障排查

### 1. 网页路由失效（详情页打不开）
- **表现**：访问 `/archives/编号` 显示 404 或者变成下载文件。
- **修复**：检查根目录的 `_worker.js` 是否丢失或配置错误；检查是否有名为 `archives` 的文件夹冲突。

### 2. GitHub Actions 报错（脚本运行失败）
- **排查**：去 `Settings -> Secrets and variables -> Actions` 检查 `FEISHU_APP_ID` 等密钥是否过期或填错。
- **排查**：检查飞书**应用**（对的我专门部署了一个应用以让ghaction获得权限，后话）获得是否具有多维表格的“可编辑”权限。

### 3. 飞书收集表（iframe）无法加载
- **排查**：如果 `submit` 页面一直卡在“加载中”，大概率是飞书修改了跨域策略（X-Frame-Options）。检查下面的新标签页好不好，坏了就直接在飞书后台复制最新的表单链接，替换掉 `submit/index.html` 中的 `iframe src` 和 `<a href>`。是好的那就没招了，按钮改大一点或者删页面跳飞书表单吧

## 换届交接

当下一届负责人接手时，请核对以下清单：

- [ ] **飞书**：已将新负责人添加为多维表格的“所有者”或“可管理”协作者。将飞书应用（校史同步）的开发者权限转移给新负责人。
- [ ] **GitHub**：已将新负责人邀请进入 `QWHistory` 组织，并赋予 `Owner` 权限。
- [ ] **Cloudflare**：由于 `*.pages.dev` 域名不能跨账号转移，新负责人需用自己的账号重新绑定 GitHub 仓库并部署一次（选择纯静态，Build command 填 `exit 0` 或留空，Output 目录填 `/`）。
- [ ] **密钥**：通过密码管理器（如 1Password/Bitwarden）将 `App Secret` 和 `GitHub PAT` 安全地交接给新负责人。
- [ ] **本手册**：确认新负责人已经完整阅读了本 `README.md` 及“核心红线”。
